# 五题 Agent 产物重评分

这批题来自 [12 题试点设计](pilot_design.md)。试点中 R1 和 R2 是同一助手模拟的两个复核视角。评测的任务材料只提供原题和初始文件，模型输出与评分材料分开保管。原始资产和金标的下载地址及 SHA-256 见 [资产清单](pilot_review_assets.json)。

| 编号 | 任务 | 用途 |
|---|---|---|
| p3 | 表格转置到 B8 | 正常评分对照，检查输出位置和内容 |
| p6 | 用透视表统计发票号 | 复核总计行是否导致误拒 |
| p8 | 调整第一页标题样式 | 复核原评分器是否把无关文本框高度算进结果 |
| p9 | 修改第四页表格首行 | 正常评分对照，检查文本约束 |
| p10 | 等比放大并居中图片 | 用原评分器与增加比例检查的原型比较 |

## 保存运行产物

每题单独发给同一 Agent，保持模型版本、提示格式和工具权限一致。仅提供 [任务输入](agent_pilot_inputs/) 中对应子目录的文件。保留 Agent 的最终文件、可用的操作日志、模型版本和运行标识。将文件保存到一个独立的运行目录，例如：

```text
agent_outputs/run-01/
  p3/result.xlsx
  p6/result.xlsx
  p8/result.pptx
  p9/result.pptx
  p10/result.pptx
```

操作日志可在对应子目录保存为 `action_log.jsonl`。在装有 `requirements-xlsx-regression.txt` 和 `python-pptx==1.0.2` 的隔离 Python 环境中运行：

```bash
python replay_agent_pilot.py --assets <初始资产与金标缓存目录> score agent_outputs/run-01 output/agent_run_01.json --run-kind agent --run-id run-01 --agent <Agent及版本>
```

评分脚本按资产清单校验 SHA-256，保留原评分分支值与产物摘要。约定文件缺失和评分异常各有状态，不并入任务失败数。p10 的本地原型在原评分通过后，根据图片像素尺寸和四边裁切量计算可见图像的宽高比，再与图片框比例比较，当前相对容差取 1%。对 p6 和 p8，保留原评分并逐题复核产物，原型分数留空。几何比较与文档评分均在已有文件上离线运行。

## 重评分脚本的对照验证

下表来自试点已保存的受控产物，来源字段为 `fixture`。这组分数验证评分流程。

| 编号 | 对照产物 | 原评分 | 原型评分 |
|---|---|---:|---:|
| p3 | 正确转置 / 错误锚点数值 | 1 / 0 | — |
| p6 | 无总计行的透视表 / 未改动初始稿 | 0 / 0 | — |
| p8 | 保留原框高的样式稿 / 缺下划线 | 0 / 0 | — |
| p9 | 正确表格首行 / 错误表格首行 | 1 / 0 | — |
| p10 | 等比放大 / 拉伸变形 | 1 / 1 | 1 / 0 |

获得同一 Agent 的结果后，逐题对照评分与产物，记录误拒、误收、真实任务失败或证据不足。用重复发生且有操作证据的真实失败写数据工单。

## 首次真实运行 p10

Codex CLI 的产物保留原图，调整裁切后以 4:3 的图片框铺满首页。原评分给 1 分，最初的修复原型给 0 分。最初的检查把图片框比例和初始图片框比例比较，合法裁切会改变这个比例。修正后，检查使用裁切后可见图像的比例，确认该产物的相对拉伸约为 0.0009%，得 1 分。原有拉伸反例的相对拉伸约为 6.06%，仍得 0 分。 [运行评分记录](agent_run_p10.json)
