# 表格与演示文稿试点复核指南

每位复核者复制一份 [空白复核表](pilot_review.csv)，填入自己的复核者代号。保留各自的原始记录，等双方提交后再对照。首次复核时请使用本指南和空白表，暂缓阅读项目裁决表、候选清单及另一位复核者的意见。

1. **先读题和初始资产。** 按原始指令填写 `success_criteria`，写明必验条件、允许的变化及需要初始文件确认的上下文。先固定此字段，再检查评分器。缺少资产时在 `evidence` 记录缺项。
2. **再看原评测。** 通过任务 JSON 核对 `func`、`options`、`expected`、`result` 及组合方式。查看实际源码分支。在 `observed_checks` 记录实际检查及对应的题面约束。
3. **分别判 A 和 B。** 用 `Y`、`N` 或 `U` 填写两个维度。A 的 `Y` 需要一个合理结果被拒的证据，B 的 `Y` 需要一个违反明确约束的结果被接受的证据。尽量提供实际分数和对照产物。只有源码推断、资产缺失或语义无法确定时判 `U`。填 `N` 时写清已检查的范围与依据。
4. **提交后复核分歧。** 按 `task_id` 对齐两份表，逐项记录 A/B 的原判、分歧原因、补充证据和裁决。重点区分题意分歧、初始状态差异与评分实现差异。证据仍不足时保留 `U`，以可复现证据更新正式裁决表。

建议先用按月汇总和 PPTX 错图这两个已跑通的案例校准术语。前者练习区分题意允许的排列与固定金标，后者练习控制变量。两例均在试点清单之外。
